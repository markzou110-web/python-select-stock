# Alpha Vision 代码逻辑分析与胜率提升后续开发计划

**日期**：2026-07-11  
**文档类型**：代码审计、策略研究与后续开发规划  
**适用范围**：`backend/`、`frontend/`、本地行情数据库与 Bark/模拟交易闭环  
**核心目标**：提高样本外、可成交、扣除成本后的交易质量；不以增加信号数、提高表面胜率或保证收益为目标。

**实施状态（2026-07-11）**：核心后端能力已完成首版，包括点时快照与审计、可执行标签、多窗口 walk-forward、发现池分流、小样本概率收缩、特征边际诊断、确认价事件、资本风险和 Champion/Challenger 晋级闸门。正式策略参数未自动调整；新能力需先积累 OOS/影子样本。

> 本文基于当前仓库静态代码与已有研究文档整理。文中的目标值是上线门槛，不是收益承诺；涉及近期策略表现的结论，仍应以版本锁定后的本地数据重跑结果为准。

## 1. 执行摘要

系统已经形成较完整的量化工作流：多源行情同步 → 数据预检 → 全市场候选过滤 → 指标和策略信号 → 市场/板块/个股决策 → SOP 分级与交易闸门 → Bark/观察池/模拟交易 → 后验校准与策略健康控制。

现阶段的主要矛盾不是指标太少，而是研究口径与真实执行仍有距离：

1. 主扫描先要求当日上涨，回踩、缩量企稳和弱转强前夜等候选可能在进入策略前就被排除。
2. 实时快照与本地降级数据的字段完整度不同；本地无换手率、市值时会绕过对应过滤，使同一参数在不同数据模式下含义不同。
3. 当前 `run_walk_forward_experiment` 只做一次按时间 70/30 切分，不是多窗口、跨市场周期的滚动 walk-forward。
4. 后验校准以信号日收盘和未来收盘为主，不能完全代表次日可买、涨停买不到、停牌、冲击成本、盘中止损等真实成交路径。
5. `Score`、校准分、SOP 分、Grade、交易桶、可交易标记和健康熔断较多；虽然已有语义拆分，但评分仍存在相关信息重复加权和固定阈值过拟合风险。
6. 组合风险已有持仓数、行业数和计划风险约束，但还没有用“仓位金额 × 止损距离”统一计算账户资本风险，也缺少相关性与流动性容量约束。

因此，后续优先顺序应为：

> 可重复数据集 → 点时无偏标签 → 多窗口样本外验证 → 候选召回与排序分离 → 概率校准 → 组合级风险与执行闭环。

### 1.1 本文关键口径

- **点时数据（point-in-time）**：只包含信号时刻已经公开且系统已经取得的数据；历史股票池、行业、ST 状态和市值不能使用当前值回填。
- **成熟样本**：目标持有期已经走完，且入场、退出所需行情完整的可执行信号；未成熟信号不进入该周期分母。
- **净胜率**：扣除佣金、印花税、滑点后净收益大于 0 的成熟交易数 / 全部成熟交易数。
- **净期望**：成熟交易净收益率的算术平均；同时报告中位数和 Profit Factor，防止极端值误导。
- **基线/Champion**：本轮实验开始前冻结的正式策略版本、参数、数据集和执行模型组合。
- **相对基准**：与信号及持有期同日期的沪深 300 收益之差；若策略股票池另有明确基准，应在实验清单中冻结。
- **关键字段**：策略实际使用或进入硬过滤的价格、成交量、换手率、流通市值、股票状态、行业、板块和事件时间戳。
- **基本单调**：至少三个连续 OOS 窗口中，概率相邻分桶的合并后验净期望不逆序；单窗口小样本只报告，不触发上线。

市场状态标签、费用、滑点、同 K 线止盈止损优先级、各板块历年涨跌停规则和复权规则，必须写入每次实验的 `execution_model_version`，不能依赖代码外的默认理解。

## 2. 当前软件功能与代码逻辑

### 2.1 总体链路

```mermaid
flowchart LR
    A["多源行情与基础数据"] --> B["同步、质量诊断、数据预检"]
    B --> C["市场快照与候选初筛"]
    C --> D["技术指标与策略信号"]
    D --> E["市场状态、板块强度、资金与价格行为"]
    E --> F["决策层、SOP Grade、交易桶"]
    F --> G["Bark、观察池、模拟/实盘记录"]
    G --> H["后验校准、策略健康、执行复盘"]
    H --> C
```

### 2.2 数据层

主要能力：

- `core/multi_source_sync.py`、`core/direct_sources.py`：多源日线和实时数据获取、重试、限速与降级。
- `core/data_source_quality.py`、`core/source_comparison.py`：数据源质量与异常复权断点诊断。
- `core/scan_preflight.py`：扫描前检查数据日期、覆盖度和历史深度。
- `core/db.py`、`core/models.py`：日线、扫描历史、推荐事件、观察池、模拟交易、审计日志等持久化。

当前优点是数据异常已有熔断和审计；风险是不同数据源的价格复权、成交量单位、字段缺失和时间戳仍可能改变筛选语义。

### 2.3 扫描与策略层

`core/scanner.py::perform_market_scan` 是主入口，当前大致流程为：

1. 读取市场状态，并按 `bull / bear / volatile` 自适应调整策略参数。
2. 执行扫描预检；严重异常时返回空结果。
3. 优先使用实时快照，失败时使用 `daily_k` 本地数据。
4. 初筛沪深目标市场、排除 ST/退市、要求当日涨幅大于 0，并按可用字段过滤换手率和市值。
5. 批量读取历史日线并计算 EMA、RSI、MACD、布林带、ATR、RS、Pine/TV 等指标。
6. 执行 `squeeze`、`pine`、`tv_zp`、`tv_dual`、`tv_dual_strict`、`consensus` 等策略。
7. 叠加价格行为、板块强度、个股板块适配、资金流、基本面、失败样本和风险信息。
8. 计算质量分、Grade、交易桶、阻断原因和最终排序，保存扫描结果与审计信息。

当前生产倾向是 `tv_dual_strict` 作为严格确认层，`tv_dual`、`sector_watch`、`early_value` 更适合发现或研究，不能简单等同于买入信号。

### 2.4 市场、板块和决策层

- `core/data.py` 与 `core/market_regime.py`：指数状态与自适应参数。
- `core/sector_strength.py`、`core/limit_up_leadership.py`：板块动量、广度、阶段和核心股识别。
- `core/price_action.py`、`core/eight_rules.py`：趋势、突破、交易区间、H1/H2、量价和失效结构。
- `core/decision_layer.py`、`core/decision_semantics.py`：市场周期、机会分、仓位上限、结构质量与动作语义。
- `core/score_calibration.py`、`core/strategy_health.py`：分数校准和近期负期望自动降权/暂停。

这层已经具备“市场—板块—个股”多级过滤，方向正确。下一步应验证每个维度的边际信息量，避免板块强度、联动分、机会分和最终分重复表达同一事实。

### 2.5 回测、复盘与风控层

- `core/backtest_lab.py`：事件式单股回测，支持次日开盘确认、固定止损、ATR 移动止盈、时间止损、滑点、佣金、印花税、整手交易和基准收益。
- `core/batch_experiment.py`：批量实验与一次时间切分的样本内/样本外对比。
- `core/outcome_calibration.py`：按 1/3/5/10 日、策略、Grade、交易桶、市场状态等计算后验表现和 blocker 区分度。
- `core/entry_timing_report.py`：比较尾盘买与次日开盘买。
- `core/portfolio_risk.py`、`core/risk_engine.py`、`core/sentinel.py`：组合限制、个股风险位、持仓监控和推送。
- `core/analytics.py`：统一胜率、盈亏比和回撤等指标口径。

这部分已明显优于简单“未来 N 日收盘涨跌”的回测，但批量研究尚未完整覆盖组合并发、真实涨跌停成交、停牌、流动性冲击和历史股票池变化。

### 2.6 前端与运营层

前端提供扫描、结果表、个股详情、图表、回测、复盘、观察池、模拟交易、系统健康和专业驾驶舱等界面。产品层最重要的原则应继续保持：

- Grade 表示结构质量。
- `trade_bucket` 表示当前动作。
- `trade_eligible` 是执行闸门。
- 排序分只在同一动作层内排序，不能绕过执行闸门。

## 3. 影响真实胜率的主要问题

### 3.1 候选召回与策略目标冲突

主扫描初筛固定要求 `pct_chg > 0`。这适合突破和强势确认策略，却会系统性遗漏：

- 强板块中的缩量回踩股；
- 收盘微跌但守住关键支撑的 H2 候选；
- 下跌日完成洗盘、次日才确认的弱转强候选。

建议把“发现池”和“交易确认池”拆开。发现池追求召回率，可允许小幅下跌；确认池再按策略要求收紧。不要直接删除涨幅过滤，否则会显著扩大计算量和噪声。

### 3.2 在线与离线扫描不完全等价

本地 `daily_k` 回退生成的快照没有可靠换手率和总市值，当前逻辑在字段为空时跳过过滤。这会造成：相同模板在线运行和离线复盘得到不同候选集。

建议显式保存 `data_mode`、字段完整度和实际生效过滤器；研究对比只能在相同数据模式下进行。若关键字段缺失，交易级扫描应降级为研究模式，而不是静默放行。

### 3.3 市场状态粒度不足且存在双口径

系统同时存在基于指数相对 EMA20 的 `OFFENSIVE/DEFENSIVE/CRITICAL`，以及基于 MA20/MA60 的 `bull/bear/volatile` 映射。映射能保持代码兼容，但会损失趋势强度、波动率、市场广度和风格轮动信息。

建议市场状态至少增加：趋势、波动、广度、成交额和大小盘风格五个正交特征；状态主要控制仓位与最低确认强度，不直接替代个股排序。

### 3.4 当前样本外验证仍不够严格

一次 70/30 切分容易被特定行情主导，也不能模拟“每月只用当时可见数据调参、下月验证”的真实研究流程。批量结果使用各股票胜率简单平均时，还会让小样本股票与大样本股票权重相同。

需要升级为多折滚动 walk-forward，并同时输出：

- 按交易笔数加权的总体指标；
- 按股票等权指标；
- 按日期/组合等权指标；
- 每个窗口的稳定性和置信区间。

### 3.5 标签没有完全反映可成交结果

`outcome_calibration` 的未来收盘收益适合快速研究，但“未来上涨”不等于“策略可成交盈利”。例如次日一字涨停无法买入，盘中先止损后反弹也不能按第 5 日收盘记为盈利。

后续应同时保留三类标签：

1. **方向标签**：未来 N 日收盘收益，衡量选股方向。
2. **路径标签**：最大有利/不利变动、先止损还是先止盈。
3. **可执行标签**：按指定入场、涨跌停、停牌、滑点和退出规则得到的净收益。

产品交易闸门只能使用第三类标签校准；前两类用于诊断。

### 3.6 胜率不是唯一优化目标

提高胜率可能通过缩小止盈、扩大止损实现，却降低长期期望。正式目标函数应至少包含：

`净期望 = 胜率 × 平均盈利 - 败率 × 平均亏损 - 交易成本`

同时约束最大回撤、尾部亏损、换手率、容量和相对基准超额收益。胜率只作为其中一个可解释指标。

### 3.7 组合风险仍需资本化

当前组合风险包含持仓数、行业数和 `pa_risk_pct` 汇总，但简单相加百分比没有考虑每笔仓位金额。建议统一为：

`单笔资本风险 = 仓位市值 × |入场价 - 止损价| / 入场价`

再以账户净值为分母汇总，并增加行业相关性、同主题暴露、流动性容量和隔夜跳空压力测试。

## 4. 后续开发路线

## P0：建立可信、可复现的研究底座

### P0-1 冻结点时数据集

**目标**：任何历史日期的扫描只使用当时可获得的数据。

开发内容：

- 保存股票池成员、ST/退市状态、行业归属、流通市值、换手率和数据源时间戳的历史快照。
- 明确前复权/后复权/不复权用途；信号、成交和止损使用一致口径。
- 每次实验生成 `dataset_version`、数据截止时间、缺失率和异常代码清单。
- 退市股票保留在历史研究池，避免幸存者偏差。

验收：同一冻结输入、随机种子、`dataset_version + strategy_version + params` 重跑，候选代码与信号时点完全一致；浮点指标绝对误差小于 `1e-8`。外部实时接口不得参与冻结实验。

### P0-2 建立可执行标签引擎

**目标**：把“方向正确”与“实际能赚”分开。

开发内容：

- 统一生成 1/3/5/10 日方向、MFE、MAE、先止盈/先止损和净交易收益标签。
- 建模 T+1、涨跌停、停牌、次日高开过滤、佣金、印花税、滑点和最小成交单位。
- 复用 `backtest_lab` 的成交逻辑，避免校准模块另写一套简化规则。
- 保存 `label_version` 和 `execution_model_version`。

验收：按策略和市场状态分层、固定随机种子抽取 50 笔交易，使用统一复核模板检查入场、T+1、涨跌停、同 K 线先止损后止盈的保守规则及退出；成交状态一致率 100%，净收益率误差小于 0.01 个百分点。

### P0-3 真正的滚动 walk-forward

**目标**：只接受跨窗口稳定的样本外优势。

建议默认：训练 18 个月、验证 3 个月、测试 3 个月，每 3 个月向前滚动；参数只在训练/验证段选择，测试段一次性冻结评估。

验收：

- 冻结一种市场状态口径；每类状态至少包含 2 个独立测试窗口，否则标记数据不足。
- 输出每窗口交易数、净胜率、净期望、Profit Factor、最大回撤、超额收益和 95% bootstrap 区间。
- 不允许只展示合并总结果；半数以上窗口为负期望的方案不得上线。

### P0-4 数据模式一致性闸门

**目标**：阻止字段缺失改变策略定义。

开发内容：扫描审计新增 `data_mode`、`effective_filters`、关键字段覆盖率；换手率、市值或实时价缺失时明确降级为 `RESEARCH_ONLY`。

验收：在线与离线使用同一 `as_of`、同一冻结完整快照时，候选代码集合差异为 0；真实时点不同的快照只做差异解释，不要求结果相同。报告必须输出字段覆盖率、实际生效过滤器及逐代码首个差异原因。

## P1：提高候选纯度与概率可解释性

### P1-1 发现池与确认池分离

新增三个互不混算的候选入口：

- `MOMENTUM_DISCOVERY`：当日上涨、放量、板块扩散，服务突破策略。
- `PULLBACK_DISCOVERY`：强板块内小幅回调、缩量、守关键位，服务 H2/回踩策略。
- `EARLY_DISCOVERY`：成本位置较低、尚未确认，只进入观察池。

只有通过确认价、量能、板块阶段和风险收益检查后才进入 `TRADE`。

验收：分别统计召回率、确认转化率、确认后胜率和从发现到确认的等待时间；不得把发现池表现计入交易策略胜率。

### P1-2 评分去冗余与消融实验

对市场、板块、个股相对强度、价格行为、量能、资金、历史胜率和 blocker 逐项做 ablation：每次移除一个特征组，比较样本外净期望变化。

验收：没有稳定边际增益的字段只能保留解释用途，不得参与加分或硬否决；同源 blocker 合并为一个主因。

### P1-3 从规则分升级为分层概率

先使用已有依赖和简单模型，不新增复杂深度学习：

- 基线：Beta-Binomial/Wilson 小样本收缩。
- 校准：按策略 × 市场状态做 isotonic 或 logistic calibration。
- 输出：`p_win`、预期净收益、样本数、置信区间和模型版本。

验收：Brier Score、校准曲线和分桶单调性优于当前固定分数；只有校准后概率和净期望同时达标才进入交易桶。

### P1-4 市场与板块分层健康控制

策略健康键扩展为 `策略 × 市场状态 × 板块阶段 × 入场形态 × 版本`，并用层级回退处理小样本：细分样本不足时回退到策略级，不对小样本直接永久暂停。

验收：每次暂停、降权、恢复都能展示成熟样本、窗口、原因和版本；恢复必须依靠新增成熟样本。

## P2：优化入场、退出与组合收益

### P2-1 入场事件研究

把确认价从静态字段变成事件流：首次接近、盘中突破、尾盘站稳、次日确认、回落失效。比较尾盘、次日开盘、回踩确认三种入场方式。

验收：每种入场模式至少 50 笔成熟可执行样本；选择规则以样本外净期望和 MAE 为准，不只看胜率。

### P2-2 退出规则按波动与市场状态验证

当前固定止损 + ATR 移动止盈 + 时间止损结构合理，后续只做有限网格：ATR 倍数、最长持有天数和时间止损，不新增大量退出规则。

验收：参数在相邻区间表现平滑，不能只在单点最优；加入成本后仍有正期望，且最大回撤不劣于基线。

### P2-3 资本风险仓位模型

按止损距离决定仓位，并设置账户、行业、主题和单策略风险预算。增加“一字跌停/连续跌停”跳空压力场景。

验收：任一新仓可计算最坏计划亏损金额；正常止损情景下单笔资本风险不超过账户净值的既定比例，组合风险不超过总预算。

### P2-4 流动性和容量模型

增加成交额、自由流通市值、预计下单金额占 ADV 比例和涨停可买性约束。资金流指标必须标注来源、时间和口径，弱数据不得成为硬加分。

验收：回测成交额约束与真实订单规模一致；容量不足的候选自动降为观察。

## P3：产品化和持续运营

### P3-1 策略研究看板

前端统一展示版本、数据模式、成熟样本、样本外指标、概率校准、健康状态和最近漂移。默认隐藏未成熟分层的排名，避免小样本冠军误导。

### P3-2 Champion/Challenger 发布机制

- Champion：当前正式策略，只允许冻结参数运行。
- Challenger：新参数或新特征，只记录影子信号，不推正式买入。
- 晋级条件：连续至少 3 个 OOS 窗口达标，且纸面交易满最小样本。
- 回滚条件：滚动净期望转负、回撤越线、数据质量异常或校准显著漂移。

### P3-3 执行归因报告

每周把结果拆成：选股 Alpha、入场时机、滑点、仓位、退出纪律和未按计划执行。系统信号收益与账户收益必须分栏展示。

## 6. 统一验收指标

### 6.1 研究可信度

- 所有报告展示数据、策略、评分、标签和执行模型版本。
- 未成熟样本不进入对应周期统计。
- 同一冻结实验重跑结果一致。
- 参数选择与最终测试区间严格隔离。
- 同时报告交易数与置信区间，不允许只报胜率百分比。

### 6.2 策略上线门槛

建议将以下指标作为候选门槛，而非收益承诺：

| 指标 | 建议门槛 |
|---|---:|
| OOS 可执行成熟交易数 | ≥100；细分桶 ≥30 仅作初步判断 |
| OOS 净胜率 | ≥52%，且置信区间不显著劣于基线 |
| OOS 净期望 | >0 |
| Profit Factor | ≥1.30 |
| 相对基准超额收益 | >0 |
| 滚动窗口稳定性 | 至少 3 个连续测试窗口达标 |
| 最大回撤 | 不高于现有 Champion 风险预算 |
| Grade/概率分桶 | 后验收益基本单调 |
| 计划字段完整率 | ≥95% |

若策略胜率低于 52% 但盈亏比和净期望显著更好，可保留；若胜率很高但净期望为负，必须拒绝上线。

### 6.3 数据和执行质量

- 实时交易级扫描关键字段覆盖率 100%。
- 信号时间不得晚于使用数据的可获得时间。
- 回测与实盘成交模型的费用、T+1、涨跌停和整手规则一致。
- 真实/模拟交易可归因到信号版本、计划价、成交价、止损价和退出原因。

## 7. 推荐实施顺序与里程碑

### 里程碑 M1：最小点时数据与审计（1~2 周）

先完成 WR-04 的最小子集：历史股票状态、行业、流通市值、换手率和数据 as-of；同步完成 WR-01。退出条件：冻结输入可复现，任何字段缺失或模式差异都有审计记录。完整历史回补可继续增量进行。

### 里程碑 M2：可执行标签与滚动验证（2~3 周）

完成 WR-02、WR-03。退出条件：同一策略得到可重复的多窗口 OOS 可执行结果，训练、验证和测试严格隔离。

### 里程碑 M3：候选分层、规则瘦身与概率校准（3~4 周）

完成 WR-05、WR-06、WR-07。退出条件：突破、回踩和早期发现互不混算；每个交易级特征有样本外边际价值，概率分桶达到本文“基本单调”定义。

### 里程碑 M4：执行和组合风险（2 周）

完成 WR-08、WR-09，再上线 WR-10 影子策略机制。退出条件：策略收益与执行损耗可分解，每笔风险金额可计算。

## 8. 测试策略

后端至少补充：

- 点时数据不能读取信号日之后的字段。
- 涨停买不到、跌停卖不出、停牌和 T+1 的成交测试。
- 滚动窗口训练/验证/测试无重叠测试。
- 小样本收缩、概率校准和分桶单调性测试。
- 在线/离线同字段输入的候选一致性测试。
- 仓位金额 × 止损距离的资本风险测试。

集成测试至少覆盖：固定数据集 → 扫描 → 保存信号 → 标签成熟 → 校准报告 → 健康状态变化。前端重点测试 Grade、交易桶、概率和“研究中/可执行”文案，防止展示层误导。

## 9. 明确不建议做的事情

1. 暂不增加 KDJ、OBV、DMI 等指标来追求更多共振；先证明现有特征的边际价值。
2. 不直接降低 A 级或 `TRADE` 阈值来增加出票。
3. 不用全样本最优参数直接上线，也不在最终测试集上反复调参。
4. 不把 `sector_watch`、`early_value` 或原始 H1/H2 直接定义为买点。
5. 不用单个市场窗口、单只股票平均胜率或少于 30 笔的分桶下稳定结论。
6. 不以胜率作为唯一目标，不通过放大止损换取表面高胜率。
7. 不在关键行情字段缺失时静默使用宽松过滤进入交易级输出。
8. 不引入新的机器学习依赖，除非简单校准基线已证明不足并经过单独评审。

## 10. 最终建议

当前系统最有价值的资产是已经具备完整闭环和大量可解释字段。下一阶段最能提升真实胜率的工作，不是再造一个策略，而是让每个信号都能回答四个问题：

1. 这个信号在当时是否真的可被系统发现？
2. 它在当时是否真实可成交？
3. 它的优势是否在多个样本外窗口稳定存在？
4. 最终盈亏来自选股、入场、仓位还是退出？

先完成 P0，再讨论调分和新模型。只有当数据、标签和验证过程可信后，策略胜率的提升才具有可复现、可上线和可持续的意义。
