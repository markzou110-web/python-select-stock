# Alpha Vision 专业化改进审计

更新日期：2026-05-31

## 当前判断

系统已经具备 A 股本地量化工具的核心闭环：数据同步、全市场扫描、策略模板、Brooks 价格行为分析、复盘中心、观察池、模拟/实盘记录、Bark 风险告警。下一阶段要提升“专业性”，重点不应只是继续堆指标，而是增强可验证性、可运营性、可复盘性和风险约束。

## 本轮已落地

1. 系统专业度自检
   - 新增后端健康快照：`GET /api/system/health`
   - 覆盖数据库连接、核心表完整性、行情覆盖、基本面覆盖、扫描历史、策略模板、Bark 推送配置
   - 输出 `status / score / checks / summary / recommendations`

2. 设置页运营面板
   - 在前端系统配置页展示成熟度评分、关键数据规模、最近扫描日期、策略模板数量、检查项和下一步建议
   - 让日常排障从“猜哪里坏了”变成“看检查项定位”

3. 测试覆盖
   - 增加系统健康快照单元测试
   - 验证无数据库、空库、就绪库三类状态

4. 扫描前数据新鲜度闸门
   - 新增 `GET /api/scan/preflight`
   - 扫描提交前检查目标日期股票覆盖和最小历史天数覆盖
   - 错误状态阻断扫描，警告状态由用户确认后继续

5. 扫描任务审计日志
   - 新增 `scan_audit_log` 表
   - 保存扫描参数快照、策略/回测/退出规则版本、候选数、结果数、失败原因分布和耗时
   - 新增 `GET /api/system/scan-audits`

6. 回测口径版本化
   - 策略扫描结果和审计日志写入 `strategy_logic_version / backtest_engine_version / exit_rule_version`
   - 后续复盘可知道信号来自哪一版策略与退出规则

7. 组合级风险预算
   - 新增组合风险预算检查
   - 添加交易前检查总持仓、实盘持仓、行业集中度、策略集中度、单笔计划风险、组合计划风险

8. 失败样本库
   - 新增 `failure_samples` 表
   - 手动亏损平仓会自动沉淀为失败样本
   - 新增 `GET /api/system/failure-samples`

9. 数据源质量诊断
   - 新增 `GET /api/system/data-sources`
   - 汇总多数据源可用性、成功/失败次数和异常建议

10. 专业驾驶舱分析层
   - 新增 `GET /api/system/ops-summary`
   - 聚合最近扫描成功率、平均耗时、候选/入选密度、失败原因 Top、策略产出分布、失败样本分布和版本口径分布
   - 前端新增独立“专业驾驶舱”，把数据源、扫描审计、失败样本和运维聚合指标放在同一工作台

11. 扫描结果研究画像
   - 新增 `GET /api/system/research-summary`
   - 基于 `scan_history` 聚合近期策略样本、行业集中、Brooks 结构、信号类型、交易动作和分数桶
   - 专业驾驶舱增加“扫描结果画像”，用于判断当前入选结果是否过度集中在某类策略或结构

12. 策略回测模块
   - 新增 `GET/POST /api/backtest/single` 单股策略回测接口
   - 复用现有策略信号函数，按单仓位顺序执行，避免同一股票重叠持仓导致收益虚高
   - 前端新增“策略回测”页面，展示胜率、总收益、最大回撤、盈亏比、权益曲线和逐笔交易明细

## 优先级建议

### P0：让结果可信

- 回测口径版本化：每次扫描保存策略参数快照、策略版本、退出规则版本，避免以后复盘时不知道当时用的是什么逻辑。
- 数据新鲜度闸门：扫描前检查 `daily_k` 最新日期、股票池数量、缺失比例，异常时给出明确提示。
- 策略命中解释统一：所有策略输出统一字段：入场条件、无效条件、止损、目标、风险收益比、避免原因。

### P1：让风险更专业

- 组合级风险预算：限制单行业、单策略、单日新增、总持仓风险暴露。
- 亏损熔断：连续亏损、单周回撤、同策略失效时自动降档或暂停推送。
- 交易计划复盘：对每笔模拟/实盘记录保存原始信号、Brooks 结构、市场状态，便于后验分析。

### P1：让复盘更有决策价值

- 策略分层胜率：按市场状态、策略类型、Brooks 信号质量、行业趋势、信号日期分组统计。
- 参数漂移分析：记录不同参数模板在不同市场环境下的表现，自动推荐“保守/平衡/进攻”模板。
- 失败样本库：把止损、失败突破、低胜率信号自动归档，形成反面案例。

### P2：让系统更像专业工作台

- 系统健康页独立导航：从设置页扩展为完整“运维中心”，显示数据源、同步历史、任务队列、最近错误。
- 数据源质量对比：Sina/Tencent/AkShare 多源价格、成交量差异监控。
- 扫描任务审计日志：保存耗时、候选数、入选数、失败原因分布、异常股票列表。

### P2：让策略研究可扩展

- 策略注册表：把策略输入、输出、默认参数、回测函数、解释字段注册成结构化配置。
- 批量实验框架：支持按日期区间、行业、市场状态跑策略实验。
- 指标一致性测试：每个新增指标都配最小样本、空值处理、边界行情测试。

## 建议的下一步实施顺序

1. 独立运维中心页面
2. 扫描审计日志前端列表
3. 失败样本库前端复盘页
4. 参数漂移分析
5. 批量实验框架
6. 多源价格差异抽样校验

这条路线能让系统从“能筛股票”升级到“能解释、能复盘、能约束风险、能诊断自身状态”。
