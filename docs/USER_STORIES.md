## 2. 核心用户故事

### 故事 1: 盘后快速选股

**作为** 个人投资者
**我想要** 每天盘后自动扫描符合条件的股票
**这样** 我就能在第二天开盘前做好准备，不需要手动翻看5000只股票

**验收标准**:
- [ ] 扫描时间 < 10秒
- [ ] 结果按评分排序，Top 30 优先展示
- [ ] 可以清晰看到每只股票的关键指标
- [ ] 可以导出结果用于进一步分析

**使用场景**:
```
时间: 每个交易日 15:30 (收盘后)
地点: 家/办公室
设备: 电脑

步骤:
1. 打开浏览器，访问 Alpha Vision
2. 检查数据同步状态，确认今日数据已更新
3. 点击 "开始扫描"
4. 等待 5-10 秒，查看扫描结果
5. 点击每只股票，查看详细指标
6. 记录感兴趣的股票代码
7. 切换到模拟交易，创建虚拟持仓
8. 关闭浏览器，准备第二天观察这些股票
```

## 3. 完整使用流程

### 流程 1: 首次使用

```
第1天: 安装配置
---------
1. 克隆代码: git clone xxx
2. 安装依赖: pip install -r requirements.txt, npm install
3. 配置数据库: 创建 PostgreSQL 数据库
4. 启动后端: cd backend && python3 -m uvicorn api:app --reload
5. 启动前端: cd frontend && npm run dev
6. 访问: http://localhost:3000
7. 首次数据同步 (30分钟)

第2天: 第一次扫描
---------
1. 检查数据同步状态
2. 执行市场扫描
3. 查看结果，了解策略输出
4. 创建第一个模拟持仓
5. 观察后续几天表现

第7天: 参数调优
---------
1. 回顾一周的模拟交易表现
2. 调整策略参数
3. 对比不同参数的结果
4. 找到最优参数组合

第30天: 实盘验证
---------
1. 如果模拟交易表现良好
2. 选择最可靠的信号
3. 小仓位实盘买入
4. 持续观察和调整
```

---

### 流程 2: 日常使用

```
09:00 - 开盘前准备
- 打开系统，检查隔夜外盘情况
- 查看模拟持仓的隔夜状态

09:30-11:30 - 盘中观察 (可选)
- 刷新数据，关注模拟持仓变化
- 如果有强烈信号，考虑加仓

15:00 - 收盘后
- 确认数据同步完成
- 执行市场扫描
- 记录新的信号股票

15:30-16:00 - 复盘研究
- 查看模拟持仓表现
- 分析今日信号质量
- 创建新的模拟持仓

19:00-20:00 - 深度研究
- 对比历史信号
- 研究板块轮动
- 计划明天操作
```

## 4. 边界场景

### 场景 1: 网络中断

```
情况: 数据同步时网络中断
预期:
- 系统自动重试 3次
- 失败的股票记录到日志
- 已下载的数据不受影响
- 下次同步时自动断点续传

用户操作:
1. 查看同步日志: "失败: 123/5000"
2. 点击 "重试失败项"
3. 系统仅重新同步失败的股票
```

---

### 场景 2: 市场异常波动

```
情况: 大盘暴跌 5%，全市场无符合条件股票
预期:
- 扫描结果为空
- 系统提示: "当前市场条件下暂无符合条件的股票"
- 显示今日市场概况

用户操作:
1. 看到空结果，不慌张
2. 查看大盘指数，确认市场环境
3. 决定: 今天空仓，等待机会
```

---

### 场景 3: 数据源故障

```
情况: akshare API 限流或不可用
预期:
- 扫描自动切换到 "本地数据模式"
- 系统提示: "网络数据源不可用，使用本地缓存"
- 功能正常，但数据可能不是最新

用户操作:
1. 看到提示，理解情况
2. 继续使用系统，基于本地数据分析
3. 等待 akshare 恢复后再增量同步
```

---

### 场景 4: 数据库损坏

```
情况: PostgreSQL 数据库异常
预期:
- 系统检测到连接失败
- 前端显示友好错误提示
- 提供数据库修复指引

用户操作:
1. 看到错误: "无法连接到数据库"
2. 按照指引检查数据库状态
3. 必要时重新初始化数据库
4. 重新同步数据 (约30分钟)
```
